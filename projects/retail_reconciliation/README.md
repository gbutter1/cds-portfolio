# Multi-System Reconciliation

**Sector:** Retail / finance operations
**Question answered:** Do a retailer's five systems agree with each other, and
where they don't, what is the gap worth, which system is wrong, and what should
someone do about it this week?

**Live report:** https://gbutter1.github.io/cds-portfolio/reports/retail-reconciliation/

## The business

Peachtree Supply Club is a fictional warehouse club with three Atlanta-area
stores (Duluth, Kennesaw, McDonough). Each store has a retail floor, a café and
an auto center. 26 weeks of data, March 30 to September 27, 2026: about
435,000 records and $16.6 million in sales.

## Source data

Generated by `generate.py` from a fixed seed, as eleven extracts from five
systems, each in that system's own format:

| System | Files | Quirks the pipeline has to handle |
|---|---|---|
| Retail registers | `retail_pos_lines.csv` | 8-digit SKUs with leading zeros |
| Merchandising | `products.csv`, `price_book.csv` | prices change mid-period |
| Café registers | `cafe_menu.csv`, `cafe_shift_sales.csv`, `cafe_shift_tenders.csv` | MM/DD/YYYY dates, mixed-case codes, shift batches that sometimes close the next day |
| Auto center | `auto_work_order_lines.csv`, `auto_part_xref.csv` | vendor part numbers, hand-typed codes, `$1,234.50` amounts, `4/12/2026 3:42 PM` times |
| Inventory | `inventory_movements.csv` | SKUs without leading zeros |
| Accounting | `gl_journal.csv` | entity codes, YYYYMMDD dates, debit/credit columns |
| Bank | `bank_transactions.csv` | processor, merchant ID and batch date buried in free text |

Deliberate, realistic mismatches are built in: café batches closed a day late,
register sales posted to the wrong store, auto labor posted to the retail
account, a duplicated manual journal entry, short, missing and late card
settlements, a processor charging above its contract rate, cash bags over and
short, installed parts never taken out of inventory, unrecognized part
numbers, registers still charging an old price, and items sold that were never
set up. In mid-July two process fixes go in, so several of these fall off.

## Pipeline

1. `python projects/retail_reconciliation/generate.py` → `data/raw/retail_reconciliation/*.csv`
2. `python pipeline/load_raw.py retail_reconciliation` → `raw_retail_reconciliation.*` (all text)
3. `python pipeline/run_dbt.py build` → reference seeds, `staging.stg_rr_*` views, `marts.rr_*` tables, 60 tests
4. `python pipeline/build_recon_report.py` → one static HTML report per week, plus a CSV of exceptions

## Reference tables (dbt seeds)

| Seed | Purpose |
|---|---|
| `rr_store_xref` | ties every system's store code (register, café, shop, ledger entity, merchant IDs) to one `store_id` |
| `rr_gl_accounts` | chart of accounts with the department behind each revenue account |
| `rr_processors` | card processors and armored-car service with contract fee rates |

## Model

| Table | Grain |
|---|---|
| `marts.rr_daily_department_sales` | store × day × department |
| `marts.rr_recon_sales_vs_gl` | store × day × department, with the explanation for each difference |
| `marts.rr_recon_card_vs_bank` | processor × store × batch date |
| `marts.rr_recon_cash_vs_bank` | store × day |
| `marts.rr_recon_auto_parts_vs_inventory` | work order line |
| `marts.rr_recon_product_master` | store × SKU × week |
| `marts.rr_exceptions` | one row per problem, with amount, severity, likely source and next step |
| `marts.rr_check_summary` | week × check |
| `marts.rr_weekly_scorecard` | week × store × department |

## Assumptions

Sales are net of discounts and exclude 7% sales tax; card and cash deposits
include tax. Cost uses product-master cost for merchandise and parts, the
menu's food-cost percentage for the café, and a standard 45% of labor revenue
for auto center labor.

## About the data

The integration patterns (crosswalks, normalized match keys, tolerance-based
matching, explained differences) are the same ones used in enterprise ETL work
on DataStage, Azure Data Factory, SQL Server and Snowflake. The company, stores
and data here are invented.
